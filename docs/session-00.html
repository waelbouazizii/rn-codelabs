Session 00 - IAM2 React Native

Prérequis & objectifs

Objectif

Cette page se fait à la maison, avant la séance 01, en une heure environ. À la fin, votre PC et votre téléphone sont prêts : une application Expo créée sur le PC s'affiche sur votre téléphone dans Expo Go, votre dépôt GitHub existe et votre projet Firebase est créé pour la séance 04.

Avant la séance

Dès qu'Expo Go est installé sur votre téléphone (Étape 1), ouvrez-le et lisez la version de SDK qu'il prend en charge. Elle doit correspondre au SDK utilisé sur cette page : SDK 57, et à l'option --template default@sdk-57 des commandes. Sur iPhone, seule la version de l'App Store fonctionne : en cas d'écart, attendez la mise à jour de la page au lieu d'installer une autre version d'Expo Go. Sur Android, laissez Expo CLI proposer la version d'Expo Go adaptée ou téléchargez-la sur expo.dev/go.

Ce qu'il vous faut

  • un PC sous Windows 10 ou 11 (macOS et Linux conviennent aussi), avec le droit d'installer des logiciels ;
  • un téléphone Android ou un iPhone, connecté au même réseau Wi-Fi que le PC ;
  • une adresse e-mail pour créer les comptes Expo, GitHub et Firebase (compte Google) ;
  • environ 3 Go d'espace disque libre.

Aucun outil de compilation native n'est nécessaire : le téléphone avec Expo Go est la seule cible.

Objectif

Durée : 15 min. Installer sur le PC Node.js 24 LTS, Git et VS Code avec trois extensions, puis installer Expo Go sur le téléphone depuis le store.

Commandes

Ouvrez PowerShell (menu Démarrer, PowerShell).

PowerShell (Windows) :

winget install OpenJS.NodeJS.LTS
winget install Git.Git
winget install Microsoft.VisualStudioCode

Sur macOS ou Linux, installez Node.js 24 LTS depuis nodejs.org, Git depuis git-scm.com et VS Code depuis code.visualstudio.com. Toutes les autres commandes de cette page sont identiques.

Fermez le terminal, ouvrez-en un nouveau, puis vérifiez les versions.

Bash et PowerShell (identique) :

node -v
npm -v
git --version
code --version

Installez les trois extensions VS Code du cours : Expo Tools, ESLint et Prettier.

Bash et PowerShell (identique) :

code --install-extension expo.vscode-expo-tools
code --install-extension dbaeumer.vscode-eslint
code --install-extension esbenp.prettier-vscode

Dans les deux commandes suivantes, remplacez le nom et l'adresse par les vôtres avant d'exécuter. Git les inscrit dans chaque commit.

Bash et PowerShell (identique) :

git config --global user.name "Prenom Nom"
git config --global user.email "prenom.nom@example.com"

Sur le téléphone, installez Expo Go depuis le Play Store (Android) ou l'App Store (iPhone).

Code complet

Aucun code à écrire dans cette étape.

Résultat attendu

La commande node -v affiche v24 (24.3 ou plus) ou v22 (22.13 ou plus). Les commandes git --version et code --version affichent un numéro de version. Expo Go est installé sur le téléphone.

Vérification

  • La commande node -v affiche une version v24 ou v22, jamais v23 ni v25.
  • La commande git config --global user.name affiche votre nom.
  • Dans VS Code, le panneau Extensions liste Expo Tools, ESLint et Prettier.
  • Sur le téléphone, Expo Go s'ouvre et indique qu'il prend en charge le SDK 57.

À retenir

Pourquoi ? Avec Expo Go, le PC ne compile aucun code natif : Node.js exécute Metro, le serveur qui assemble votre JavaScript, et Expo Go contient déjà la partie native de l'application. C'est pour cela que la chaîne Gradle que vous utilisez en Kotlin n'intervient pas ici.

Si node -v affiche une autre version majeure que 24 ou 22, désinstallez Node.js puis installez la version 24 LTS depuis nodejs.org. Expo SDK 57 est validé pour ce cours avec Node.js 24 et 22 uniquement.

Erreurs fréquentes : Si le terminal répond que node, git ou code est une commande inconnue juste après l'installation, le terminal a été ouvert avant l'installation : fermez-le et ouvrez-en un nouveau.

Objectif

Durée : 10 min. Créer un compte Expo gratuit et se connecter avec ce même compte dans le terminal du PC et dans Expo Go sur le téléphone.

Commandes

Créez un compte gratuit sur expo.dev/signup avec une adresse e-mail et un mot de passe, et notez votre nom d'utilisateur.

Connectez le terminal à ce compte. La commande pose des questions : répondez avec votre nom d'utilisateur et votre mot de passe. Si npx propose de télécharger un paquet, acceptez.

Bash et PowerShell (identique) :

npx expo login

Vérifiez ensuite le compte connecté.

Bash et PowerShell (identique) :

npx expo whoami

Seulement si PowerShell refuse d'exécuter npx parce que l'exécution de scripts est désactivée — PowerShell (Windows) :

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Sur le téléphone, ouvrez Expo Go et connectez-vous avec le même compte.

Code complet

Aucun code à écrire dans cette étape.

Résultat attendu

La commande npx expo whoami affiche votre nom d'utilisateur Expo. Expo Go affiche le même compte sur le téléphone.

Vérification

  • Dans le terminal, npx expo whoami affiche votre nom d'utilisateur.
  • Sur le téléphone, Expo Go affiche ce même nom d'utilisateur dans l'écran du compte.

À retenir

Pourquoi ? Sur iPhone, Expo Go pour le SDK 57 n'ouvre un projet que si le terminal et l'application utilisent le même compte Expo. Sur Android, la connexion n'est pas toujours exigée aujourd'hui, mais faites-la quand même : la règle peut changer avec une prochaine version du SDK.

Erreurs fréquentes : Deux comptes différents (un sur le PC, un autre sur le téléphone) empêchent l'ouverture du projet sur iPhone. Comparez le nom affiché par npx expo whoami et celui affiché dans Expo Go.

Objectif

Durée : 5 min. Créer le dépôt GitHub qui recevra toutes vos applications du cours, puis le cloner sur le PC.

Commandes

  1. Connectez-vous à github.com (créez un compte si nécessaire).
  2. Créez un nouveau dépôt nommé iam2-rn-prenom-nom, avec votre prénom et votre nom en minuscules, sans accent ni espace.
  3. Choisissez la visibilité privée et cochez l'option qui ajoute un fichier README, pour que le dépôt ne soit pas vide.
  4. Dans les réglages du dépôt, invitez comme collaborateur le compte GitHub waelbouazizii.

Créez un dossier de travail dont le chemin ne contient ni espace ni accent, hors de OneDrive.

PowerShell (Windows) :

New-Item -ItemType Directory -Force C:\dev
cd C:\dev

Bash (macOS, Linux, Git Bash) :

mkdir -p ~/dev
cd ~/dev

Dans les commandes suivantes, remplacez USERNAME par votre nom d'utilisateur GitHub et prenom-nom par les vôtres avant d'exécuter. À la première connexion, Git ouvre une fenêtre du navigateur pour vous identifier.

Bash et PowerShell (identique) :

git clone https://github.com/USERNAME/iam2-rn-prenom-nom.git
cd iam2-rn-prenom-nom
git status

Code complet

Aucun code à écrire dans cette étape.

Résultat attendu

Le dossier iam2-rn-prenom-nom existe sur le PC et contient le fichier README.md. La commande git status indique qu'il n'y a rien à valider.

Vérification

  • Le dossier cloné contient README.md.
  • La commande git status ne signale aucune modification.
  • Cette étape ne concerne que le PC : aucune vérification sur le téléphone ici, elle reprend à l'Étape 4.

À retenir

Pourquoi ? Un seul dépôt contient un dossier par séance : s1-profile-contacts, s2-expenses, et ainsi de suite. Chaque remise est un tag Git sur ce dépôt ; c'est le tag qui est noté, pas un fichier envoyé par e-mail.

Erreurs fréquentes : Un chemin avec des espaces, des accents ou synchronisé par OneDrive provoque des erreurs difficiles à lire avec Metro et npm. Gardez un chemin court comme C:\dev.

Objectif

Durée : 10 min. Créer une application Expo SDK 57 dans votre dépôt et l'afficher sur votre téléphone avec Expo Go.

Commandes

Dans le terminal, placez-vous dans le dossier de votre dépôt (iam2-rn-prenom-nom), puis exécutez :

Terminal 1 — Bash et PowerShell (identique) :

npx create-expo-app@latest w0-hello --template default@sdk-57
cd w0-hello
npx expo start

Au premier lancement, Windows peut demander l'autorisation d'accès réseau pour Node.js : autorisez-le sur les réseaux privés. Le PC et le téléphone doivent être sur le même réseau Wi-Fi, déclaré comme réseau privé dans Windows.

Scannez le QR code affiché dans le terminal : sur Android depuis Expo Go, sur iPhone avec l'application Appareil photo.

Seulement si le QR code ne se connecte pas : mode tunnel. Arrêtez d'abord le serveur avec Ctrl+C dans le Terminal 1 — Bash et PowerShell (identique) :

npx expo start --tunnel

Le mode tunnel peut proposer d'installer un paquet supplémentaire : acceptez. Il est plus lent que le réseau local.

Code complet

Aucun code à écrire dans cette étape : vous lancez l'application de démarrage fournie par le modèle.

Résultat attendu

Le terminal affiche un QR code. Après le scan, Expo Go télécharge le JavaScript depuis votre PC et affiche l'écran de démarrage du modèle Expo.

Vérification

  • Le Terminal 1 affiche un QR code et reste en cours d'exécution.
  • Sur le téléphone, Expo Go affiche l'écran de démarrage de w0-hello.

À retenir

Pourquoi ? La commande npx expo start lance Metro sur le PC. Expo Go télécharge votre JavaScript par le Wi-Fi et l'exécute avec les modules natifs qu'il contient déjà : aucun APK n'est construit, contrairement au lancement d'un projet Kotlin ou à flutter run.

Erreurs fréquentes : Si Expo Go signale que la version de SDK du projet ne correspond pas : sur Android, laissez Expo CLI installer la version d'Expo Go adaptée ou téléchargez-la sur expo.dev/go ; sur iPhone, seule la version de l'App Store fonctionne, attendez la mise à jour de cette page. Si le chargement n'aboutit jamais, vérifiez que le PC et le téléphone sont sur le même Wi-Fi, puis utilisez le bloc tunnel.

Objectif

Durée : 10 min. Remplacer l'application de démarrage par un écran à votre nom et vérifier que chaque enregistrement met à jour le téléphone sans relancer l'application.

Commandes

Arrêtez le serveur avec Ctrl+C dans le Terminal 1, puis réinitialisez le projet. Le script demande s'il faut conserver les fichiers de démarrage : répondez n, puis Entrée, pour les supprimer.

Terminal 1 — Bash et PowerShell (identique) :

npm run reset-project

Ouvrez le dossier w0-hello dans VS Code. Si vous avez répondu autrement, un dossier example existe : supprimez-le dans l'explorateur de VS Code. Remplacez ensuite le contenu de src/app/index.tsx par le code de la carte suivante, avec votre prénom et votre nom, et enregistrez.

Relancez le serveur et rescannez le QR code si Expo Go ne se reconnecte pas seul.

Terminal 1 — Bash et PowerShell (identique) :

npx expo start

Code complet

Fichier src/app/index.tsx :

import { StyleSheet, Text, View } from 'react-native';

// Replace with your own first name and last name.
const STUDENT_NAME: string = 'Prénom Nom';

export default function Index() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>w0-hello</Text>
      <Text style={styles.text}>{STUDENT_NAME}</Text>
      <Text style={styles.text}>IAM2 - React Native avec Expo</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    alignItems: 'center',
    justifyContent: 'center',
    gap: 8,
    backgroundColor: '#ffffff',
  },
  title: { fontSize: 28, fontWeight: '700', color: '#1f2430' },
  text: { fontSize: 16, color: '#374151' },
});

Résultat attendu

Le téléphone affiche une barre de titre « index », puis trois lignes centrées : w0-hello, votre prénom et votre nom, puis IAM2 - React Native avec Expo.

Vérification

  • Sur le téléphone, l'écran affiche votre prénom et votre nom.
  • Après avoir remplacé « w0-hello » par « Bonjour IAM2 » dans le code et enregistré, le téléphone affiche le nouveau texte en moins de deux secondes, sans relancer Expo Go (remettez ensuite « w0-hello »).

À retenir

Pourquoi ? Fast Refresh renvoie au téléphone uniquement le module modifié et relance le rendu du composant. C'est l'équivalent du Hot Reload de Flutter et de Live Edit en Compose, avec une différence : ici aucun code natif n'est recompilé, jamais.

Erreurs fréquentes : Si le téléphone affiche encore l'ancien écran après la réinitialisation, le serveur n'a pas été relancé : arrêtez-le avec Ctrl+C, relancez npx expo start et rescannez le QR code. Si la question du script n'a pas reçu la réponse y ou n, rien n'est modifié : relancez npm run reset-project.

Objectif

Durée : 10 min. Créer dès maintenant le projet Firebase utilisé à la séance 04, avec l'authentification par e-mail et Firestore, pour ne pas perdre de temps en séance.

Commandes

Tout se passe dans le navigateur, sur console.firebase.google.com, avec un compte Google. Le forfait gratuit suffit : ne saisissez aucun moyen de paiement. Le serveur Expo de l'Étape 5 peut rester lancé.

  1. Créez un projet nommé iam2-rn-prenom (votre prénom, sans accent). Google Analytics n'est pas nécessaire.
  2. Dans la section Authentication, activez la méthode de connexion par adresse e-mail et mot de passe.
  3. Dans la section Firestore Database, créez la base de données en mode production, dans une région européenne. La région ne peut plus être changée ensuite.
  4. N'enregistrez pas encore d'application et ne copiez aucune clé : ce sera fait à la séance 04.

Code complet

Aucun code à écrire dans cette étape.

Résultat attendu

La console Firebase affiche votre projet, la méthode e-mail et mot de passe activée dans Authentication, et une base Firestore vide.

Vérification

  • La console liste le projet iam2-rn-prenom.
  • Dans Authentication, la méthode e-mail et mot de passe est marquée comme activée.
  • Dans Firestore Database, l'onglet des règles montre des règles qui refusent toute lecture et toute écriture (mode production).
  • Cette étape ne concerne que le navigateur : aucune vérification sur le téléphone ici.

À retenir

Pourquoi ? En mode production, Firestore refuse tout tant que vous n'avez pas écrit de règles de sécurité. C'est le bon point de départ : à la séance 04, vous écrirez des règles qui n'autorisent que les utilisateurs connectés, au lieu d'ouvrir la base puis d'oublier de la refermer.

Erreurs fréquentes : Le mode test ouvre la base à tout le monde pendant une durée limitée, puis la bloque : l'application cesse alors de fonctionner sans message clair. Choisissez le mode production.
