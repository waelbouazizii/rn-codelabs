Session 02 - Persistance locale avec SQLite

Prérequis & objectifs

Objectif

En séance 01, les favoris disparaissaient à chaque fermeture de l'application : l'état vivait en mémoire. Cette séance ajoute une base SQLite sur le téléphone. Vous construisez Offline Expense Tracker : une liste de dépenses que l'on peut ajouter, modifier, supprimer, filtrer par catégorie et totaliser, et qui survit au redémarrage de l'application, sans réseau.

Avant la séance

Ouvrez Expo Go sur votre téléphone, installé depuis le store, et lisez la version de SDK qu'il prend en charge. Elle doit correspondre au SDK utilisé sur cette page : SDK 57, et à l'option --template default@sdk-57 de l'Étape 1. Sur iPhone, seule la version de l'App Store fonctionne : en cas d'écart, attendez la mise à jour de la page au lieu d'installer une autre version d'Expo Go. Vérifiez aussi que npx expo whoami et Expo Go affichent le même compte Expo. La séance fonctionne sans Internet une fois le projet créé, mais la création du projet et l'installation de expo-sqlite demandent une connexion.

À la fin de la séance, vous savez

  1. choisir entre un stockage clé-valeur (AsyncStorage, expo-sqlite/kv-store) et une base relationnelle SQLite, en les reliant à DataStore et Room, à shared_preferences et sqflite ;
  2. ouvrir une base avec SQLiteProvider et onInit, y accéder avec useSQLiteContext, et utiliser execAsync, runAsync, getAllAsync, getFirstAsync et withTransactionAsync avec async/await ;
  3. écrire des migrations versionnées avec PRAGMA user_version ;
  4. appliquer le patron dépôt (expenseRepo(db)) et écrire un hook personnalisé (useExpenses) pour qu'aucun écran ne contienne de SQL ;
  5. construire un formulaire contrôlé : TextInput, conversion d'une saisie numérique, validation simple.

Une requête prend du temps

Durée : 22 min.

  • Lire un fichier de base de données prend quelques millisecondes : expo-sqlite ne bloque pas l'interface, chaque méthode dont le nom finit par Async renvoie une Promise, c'est-à-dire une valeur qui arrivera plus tard.
  • await attend le résultat d'une Promise ; il n'est permis que dans une fonction déclarée async ; une fonction async renvoie toujours une Promise.
  • Une Promise rejetée devient une exception à l'endroit du await : on l'attrape avec try / catch.
  • Une idée fausse fréquente : « SQLite est local, donc la requête répond tout de suite, sans await ». La requête reste asynchrone, même sans réseau.

L'API expo-sqlite

Aide-mémoire, à consulter pendant les étapes :

Méthode Usage Renvoie
execAsync(sql) plusieurs instructions d'un coup, sans paramètre : création de tables, PRAGMA rien
runAsync(sql, valeurs) une écriture : INSERT, UPDATE, DELETE lastInsertRowId et changes
getAllAsync<T>(sql, valeurs) une lecture de plusieurs lignes un tableau T[], vide si aucune ligne
getFirstAsync<T>(sql, valeurs) une lecture d'une seule ligne T ou null
withTransactionAsync(fonction) plusieurs écritures indivisibles rien ; annule tout si la fonction lève une erreur

SQLiteProvider ouvre la base une fois, exécute onInit, puis affiche ses enfants ; useSQLiteContext() donne la base ouverte à n'importe quel composant ou hook placé sous le fournisseur. Le mécanisme qui transporte la base (React Context) est expliqué en séance 03.

Toujours des paramètres

Une valeur saisie par l'utilisateur ne s'insère jamais dans le texte SQL avec un gabarit de chaîne. On écrit un point d'interrogation par valeur et on passe les valeurs à part : la base les traite comme des données, jamais comme du SQL. C'est la même règle qu'avec @Query et ses paramètres dans Room.

Code annoté

Exemple à lire (TypeScript) :

import type { SQLiteDatabase } from 'expo-sqlite';

type CountRow = { count: number };

// An async function always returns a Promise: here Promise<number>.
export async function countExpenses(db: SQLiteDatabase): Promise<number> {
  // await pauses this function only; the interface keeps responding.
  const row = await db.getFirstAsync<CountRow>('SELECT COUNT(*) AS count FROM expenses');
  // getFirstAsync returns null when no row matches.
  return row?.count ?? 0;
}

export async function addCoffee(db: SQLiteDatabase): Promise<number | null> {
  try {
    // One value per question mark, in the same order.
    const result = await db.runAsync(
      'INSERT INTO expenses (label, amount, category, created_at) VALUES (?, ?, ?, ?)',
      'Café',
      1.5,
      'food',
      Date.now(),
    );
    return result.lastInsertRowId;
  } catch (e) {
    // A rejected Promise becomes an exception at the await.
    console.error(e);
    return null;
  }
}

À lire dans ce code :

  • Le type entre chevrons (getFirstAsync<CountRow>) décrit la ligne attendue. C'est une promesse de votre part : TypeScript ne vérifie pas que la table a réellement ces colonnes.
  • getFirstAsync renvoie null quand aucune ligne ne correspond : le contrôle strict de null impose row?.count ?? 0.
  • Quatre points d'interrogation, quatre valeurs, dans le même ordre.

Le schéma change, les données restent

Durée : 18 min.

  • La base vit sur le téléphone de chaque utilisateur. Quand une nouvelle version de l'application a besoin d'une colonne de plus, elle ne peut ni supprimer le fichier ni recréer la table : les données seraient perdues.
  • SQLite garde un entier libre dans le fichier, lu et écrit avec PRAGMA user_version (0 pour une base neuve). La fonction de migration lit ce numéro, applique dans l'ordre les marches manquantes, puis écrit le nouveau numéro.
  • Règle : une marche publiée ne se modifie plus. Pour changer le schéma, on ajoute une marche.
  • Une idée fausse fréquente : « CREATE TABLE IF NOT EXISTS suffit à mettre le schéma à jour ». Si la table existe déjà, l'instruction ne fait rien, même si la définition a changé.

Code annoté

Exemple à lire (TypeScript) :

import type { SQLiteDatabase } from 'expo-sqlite';

const DATABASE_VERSION = 2;

export async function migrateDbIfNeeded(db: SQLiteDatabase): Promise<void> {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  let version = row?.user_version ?? 0;

  if (version >= DATABASE_VERSION) {
    return;
  }

  // Step 0 -> 1: first installation.
  if (version === 0) {
    await db.execAsync(`
      PRAGMA journal_mode = 'wal';
      CREATE TABLE IF NOT EXISTS tasks (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        title TEXT NOT NULL
      );
    `);
    version = 1;
  }

  // Step 1 -> 2: phones that already hold data keep every row.
  if (version === 1) {
    await db.execAsync('ALTER TABLE tasks ADD COLUMN done INTEGER NOT NULL DEFAULT 0;');
    version = 2;
  }

  await db.execAsync(`PRAGMA user_version = ${DATABASE_VERSION}`);
}

// Both UPDATE statements succeed, or neither is kept.
export async function moveAmount(db: SQLiteDatabase, fromId: number, toId: number, amount: number): Promise<void> {
  await db.withTransactionAsync(async () => {
    await db.runAsync('UPDATE envelopes SET balance = balance - ? WHERE id = ?', amount, fromId);
    await db.runAsync('UPDATE envelopes SET balance = balance + ? WHERE id = ?', amount, toId);
  });
}

À lire dans ce code :

  • Les marches sont des if successifs, pas des else if : une installation neuve les enchaîne toutes.
  • La seule interpolation dans du SQL est la constante DATABASE_VERSION, écrite par vous : PRAGMA n'accepte pas de paramètre. Une valeur saisie par l'utilisateur passe toujours par un point d'interrogation.
  • withTransactionAsync exécute BEGIN, puis votre fonction, puis COMMIT ; si la fonction lève une erreur, il exécute ROLLBACK et relance l'erreur.

withTransactionAsync n'isole pas les autres requêtes lancées en même temps ailleurs dans l'application : une requête qui s'exécute pendant la transaction en fait partie. Dans l'atelier, une seule écriture est en cours à la fois, ce qui suffit. expo-sqlite propose aussi withExclusiveTransactionAsync pour les cas concurrents.

Quiz éclair

Un téléphone possède déjà la base en version 1, avec 12 lignes dans tasks. L'application est mise à jour avec le code annoté ci-dessus (DATABASE_VERSION vaut 2). Que se passe-t-il à l'ouverture ?

version vaut 1 : le bloc if (version === 0) est sauté, le bloc if (version === 1) ajoute la colonne, puis PRAGMA user_version enregistre 2. Au lancement suivant, la fonction s'arrête dès le premier test.

Dans un bloc withTransactionAsync, trois INSERT sont exécutés à la suite. Les deux premiers réussissent ; le troisième lève une erreur parce qu'une colonne NOT NULL reçoit NULL. Combien de nouvelles lignes la table contient-elle ensuite ?

Une transaction est indivisible. L'erreur fait sortir de la fonction, withTransactionAsync exécute ROLLBACK, et la base revient à son état d'avant BEGIN.

Sortir le SQL des écrans

Durée : 20 min.

  • Règle du cours (barème : 1 point) : un écran n'écrit jamais de SQL. Il appelle un hook de src/features, qui appelle un dépôt de src/db.
  • Le dépôt est une fonction qui reçoit la base et renvoie un objet de fonctions : une par requête. C'est l'équivalent d'un DAO Room. Tout le SQL d'une table est dans un seul fichier.
  • Un hook personnalisé est une fonction dont le nom commence par use et qui appelle d'autres hooks. Il regroupe l'état, l'effet de chargement et les actions, comme un ViewModel regroupe un StateFlow et ses méthodes. Les règles des hooks de la séance 01 s'appliquent à lui aussi.
  • Chaque composant qui appelle le hook obtient son propre état : un hook partage de la logique, pas des données. Deux écrans qui appellent useExpenses ne partagent donc pas la même liste. Conséquence dans l'atelier : après un ajout fait sur un autre écran, la liste doit relire la base quand elle revient au premier plan.

Code annoté

Exemple à lire (TypeScript) :

import { useSQLiteContext, type SQLiteDatabase } from 'expo-sqlite';
import { useEffect, useState } from 'react';

export type Task = { id: number; title: string; done: number };

// Repository: the only place that contains SQL for the tasks table.
export const taskRepo = (db: SQLiteDatabase) => ({
  all: () => db.getAllAsync<Task>('SELECT * FROM tasks ORDER BY id DESC'),
  add: (title: string) => db.runAsync('INSERT INTO tasks (title) VALUES (?)', title),
});

// Custom hook: a function whose name starts with "use" and that calls other hooks.
export function useTasks() {
  const db = useSQLiteContext();
  const [tasks, setTasks] = useState<Task[]>([]);
  const [reloadCount, setReloadCount] = useState<number>(0);

  useEffect(() => {
    let isCurrent = true;

    const load = async () => {
      const rows = await taskRepo(db).all();
      if (isCurrent) {
        setTasks(rows);
      }
    };

    load();

    return () => {
      isCurrent = false;
    };
  }, [db, reloadCount]);

  const addTask = async (title: string): Promise<void> => {
    await taskRepo(db).add(title);
    // The table changed: ask the effect to read it again.
    setReloadCount((count) => count + 1);
  };

  return { tasks, addTask };
}

À lire dans ce code :

  • La fonction passée à useEffect ne peut pas être async : elle doit renvoyer soit rien, soit la fonction de nettoyage. On déclare donc une fonction async à l'intérieur, puis on l'appelle.
  • isCurrent protège contre une réponse tardive : si l'effet a été nettoyé entre-temps, le résultat est ignoré. C'est le nettoyage vu en séance 01, appliqué à une requête.
  • reloadCount ne s'affiche nulle part : c'est une dépendance de l'effet. Le modifier relance la lecture.

Le champ affiche l'état

Durée : 15 min.

  • Un TextInput contrôlé reçoit sa valeur par la prop value et signale chaque frappe par onChangeText. L'état React est la seule source : le champ affiche ce que l'état contient. Vous avez utilisé ce principe dans le défi de la séance 01.
  • Un champ de saisie produit toujours une chaîne, même avec un clavier numérique. L'état garde la chaîne telle qu'elle est saisie ; la conversion en nombre se fait à la validation, pas à chaque frappe.
  • keyboardType="decimal-pad" choisit le clavier, il ne valide rien : sur un téléphone réglé en français, la touche décimale saisit une virgule. Un clavier numérique ne garantit donc pas un nombre.
  • La validation produit un message par champ ; le formulaire n'enregistre que si tous les champs sont valides.

Exemple à lire (TypeScript) :

import { useState } from 'react';
import { Pressable, Text, TextInput, View } from 'react-native';

type Props = {
  onSave: (amount: number) => void;
};

export function AmountForm({ onSave }: Props) {
  // The state holds what the user typed: a text, not a number.
  const [amountText, setAmountText] = useState<string>('');
  const [error, setError] = useState<string | null>(null);

  const handleSave = () => {
    // French keyboards type a comma: "12,5" must become "12.5" first.
    const amount = Number(amountText.trim().replace(',', '.'));
    if (amountText.trim() === '' || !Number.isFinite(amount) || amount <= 0) {
      setError('Montant invalide.');
      return;
    }
    setError(null);
    onSave(amount);
  };

  return (
    <View>
      <TextInput
        value={amountText}
        onChangeText={setAmountText}
        keyboardType="decimal-pad"
        placeholder="Montant"
      />
      {error ? <Text>{error}</Text> : null}
      <Pressable onPress={handleSave}>
        <Text>Enregistrer</Text>
      </Pressable>
    </View>
  );
}

À lire dans ce code :

  • L'état est de type string. Le nombre n'existe qu'au moment d'enregistrer.
  • Number('12,5') vaut NaN : la virgule est remplacée par un point avant la conversion.
  • Number.isFinite écarte NaN ; le test amount <= 0 écarte zéro et les valeurs négatives.

N'utilisez pas parseFloat pour une saisie : parseFloat('12,5') renvoie 12 sans signaler d'erreur, et la dépense serait enregistrée avec un montant faux.

Quiz éclair

L'utilisateur saisit 12,5 dans le champ Montant, avec un clavier décimal. Que vaut Number('12,5') ?

Number convertit la chaîne entière ou échoue avec NaN. C'est parseFloat qui s'arrête à la virgule et renvoie 12. Il faut remplacer la virgule par un point, puis vérifier le résultat avec Number.isFinite.

import type { SQLiteDatabase } from 'expo-sqlite';

export type Category = 'food' | 'transport' | 'housing' | 'leisure' | 'other';

// One row of the expenses table: the field names are the column names.
export type Expense = {
  id: number;
  label: string;
  amount: number;
  category: Category;
  created_at: number;
};

export type ExpenseInput = Pick<Expense, 'label' | 'amount' | 'category'>;

export const expenseRepo = (db: SQLiteDatabase) => ({
  all: () => db.getAllAsync<Expense>('SELECT * FROM expenses ORDER BY created_at DESC, id DESC'),

  byId: (id: number) => db.getFirstAsync<Expense>('SELECT * FROM expenses WHERE id = ?', id),

  add: (input: ExpenseInput) =>
    db.runAsync(
      'INSERT INTO expenses (label, amount, category, created_at) VALUES (?, ?, ?, ?)',
      input.label,
      input.amount,
      input.category,
      Date.now(),
    ),

  update: (id: number, input: ExpenseInput) =>
    db.runAsync(
      'UPDATE expenses SET label = ?, amount = ?, category = ? WHERE id = ?',
      input.label,
      input.amount,
      input.category,
      id,
    ),

  remove: (id: number) => db.runAsync('DELETE FROM expenses WHERE id = ?', id),
});

import { useIsFocused } from 'expo-router';
import { useSQLiteContext } from 'expo-sqlite';
import { useEffect, useState } from 'react';

import { expenseRepo, type Expense } from '@/db/expenseRepo';

export function useExpenses() {
  const db = useSQLiteContext();
  const isFocused = useIsFocused();
  const [expenses, setExpenses] = useState<Expense[]>([]);
  const [isLoading, setIsLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // Read again each time the screen comes back to the front.
    if (!isFocused) {
      return;
    }
    let isCurrent = true;

    const load = async () => {
      try {
        const rows = await expenseRepo(db).all();
        if (isCurrent) {
          setExpenses(rows);
          setError(null);
        }
      } catch (e) {
        console.error(e);
        if (isCurrent) {
          setError('Lecture de la base impossible.');
        }
      } finally {
        if (isCurrent) {
          setIsLoading(false);
        }
      }
    };

    load();

    // Cleanup: a slow answer from an older effect must not overwrite a newer one.
    return () => {
      isCurrent = false;
    };
  }, [db, isFocused]);

  return { expenses, isLoading, error };
}

  label: string;
  amountText: string;
  category: Category;
};

export type ExpenseFormErrors = {
  label?: string;
  amount?: string;
};

export const EMPTY_FORM_VALUES: ExpenseFormValues = {
  label: '',
  amountText: '',
  category: 'food',
};

// Fills the form from a stored expense: 4.5 becomes the text "4,5".
export function toFormValues(expense: Expense): ExpenseFormValues {
  return {
    label: expense.label,
    amountText: String(expense.amount).replace('.', ','),
    category: expense.category,
  };
}

// "12,5" and "12.5" both give 12.5; an empty, invalid or negative text gives null.
export function parseAmount(text: string): number | null {
  const normalized = text.trim().replace(',', '.');
  if (normalized === '') {
    return null;
  }
  // Number('abc') is NaN; rounding keeps three decimals (millimes).
  const value = Math.round(Number(normalized) * 1000) / 1000;
  if (!Number.isFinite(value) || value <= 0) {
    return null;
  }
  return value;
}

export function validateExpense(values: ExpenseFormValues): {
  input: ExpenseInput | null;
  errors: ExpenseFormErrors;
} {
  const errors: ExpenseFormErrors = {};
  const label = values.label.trim();
  const amount = parseAmount(values.amountText);

  if (label.length < 2) {
    errors.label = 'Le libellé doit contenir au moins 2 caractères.';
  }
  if (amount === null) {
    errors.amount = 'Le montant doit être un nombre supérieur à 0.';
  }

  if (label.length < 2 || amount === null) {
    return { input: null, errors };
  }
  return { input: { label, amount, category: values.category }, errors };
}

export type Category = 'food' | 'transport' | 'housing' | 'leisure' | 'other';

// One row of the expenses table: the field names are the column names.
export type Expense = {
  id: number;
  label: string;
  amount: number;
  category: Category;
  created_at: number;
};

export type ExpenseInput = Pick<Expense, 'label' | 'amount' | 'category'>;

export const expenseRepo = (db: SQLiteDatabase) => ({
  all: (category?: Category) =>
    category
      ? db.getAllAsync<Expense>(
          'SELECT * FROM expenses WHERE category = ? ORDER BY created_at DESC, id DESC',
          category,
        )
      : db.getAllAsync<Expense>('SELECT * FROM expenses ORDER BY created_at DESC, id DESC'),

  total: async (category?: Category): Promise<number> => {
    const row = category
      ? await db.getFirstAsync<{ total: number | null }>(
          'SELECT SUM(amount) AS total FROM expenses WHERE category = ?',
          category,
        )
      : await db.getFirstAsync<{ total: number | null }>('SELECT SUM(amount) AS total FROM expenses');
    // SUM returns NULL when no row matches.
    return row?.total ?? 0;

      input.amount,
      input.category,
      Date.now(),

import { useIsFocused } from 'expo-router';
import { useSQLiteContext } from 'expo-sqlite';
import { useEffect, useState } from 'react';

import { expenseRepo, type Expense } from '@/db/expenseRepo';
import type { CategoryFilter } from '@/features/expenses/categories';

export function useExpenses(filter: CategoryFilter) {
  const db = useSQLiteContext();
  const isFocused = useIsFocused();
  const [expenses, setExpenses] = useState<Expense[]>([]);
  const [total, setTotal] = useState<number>(0);
  const [isLoading, setIsLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // Read again each time the screen comes back to the front.
    if (!isFocused) {
      return;
    }
    let isCurrent = true;

    const load = async () => {
      try {
        const repo = expenseRepo(db);
        const category = filter === 'all' ? undefined : filter;
        // The two queries are independent: start both, then wait for both.
        const [rows, sum] = await Promise.all([repo.all(category), repo.total(category)]);
        if (isCurrent) {
          setExpenses(rows);
          setTotal(sum);
          setError(null);
        }
      } catch (e) {
        console.error(e);
        if (isCurrent) {
          setError('Lecture de la base impossible.');
        }
      } finally {
        if (isCurrent) {
          setIsLoading(false);
        }
      }
    };

    load();

    // Cleanup: a slow answer from an older effect must not overwrite a newer one.
    return () => {
      isCurrent = false;
    };
  }, [db, filter, isFocused]);

  return { expenses, total, isLoading, error };
}

import { useIsFocused } from 'expo-router';
import { useSQLiteContext } from 'expo-sqlite';
import { useEffect, useState } from 'react';

import { expenseRepo, type Expense } from '@/db/expenseRepo';
import type { CategoryFilter } from '@/features/expenses/categories';

export function useExpenses(filter: CategoryFilter) {
  const db = useSQLiteContext();
  const isFocused = useIsFocused();
  const [expenses, setExpenses] = useState<Expense[]>([]);
  const [total, setTotal] = useState<number>(0);
  const [isLoading, setIsLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);
  const [reloadCount, setReloadCount] = useState<number>(0);

  useEffect(() => {
    // Read again each time the screen comes back to the front.
    if (!isFocused) {
      return;
    }
    let isCurrent = true;

    const load = async () => {
      try {
        const repo = expenseRepo(db);
        const category = filter === 'all' ? undefined : filter;
        // The two queries are independent: start both, then wait for both.
        const [rows, sum] = await Promise.all([repo.all(category), repo.total(category)]);
        if (isCurrent) {
          setExpenses(rows);
          setTotal(sum);
          setError(null);
        }
      } catch (e) {
        console.error(e);
        if (isCurrent) {
          setError('Lecture de la base impossible.');
        }
      } finally {
        if (isCurrent) {
          setIsLoading(false);
        }
      }
    };

    load();

    // Cleanup: a slow answer from an older effect must not overwrite a newer one.
    return () => {
      isCurrent = false;
    };
  }, [db, filter, isFocused, reloadCount]);

  // Changing reloadCount changes a dependency, so the effect runs again.
  const reload = () => setReloadCount((count) => count + 1);

  return { expenses, total, isLoading, error, reload };
}
