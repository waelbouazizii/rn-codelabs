Rappel : une requête HTTP

Une requête HTTP est un verbe (GET pour lire, POST pour créer ou envoyer, PUT et DELETE pour modifier et supprimer) suivi d'une URL, avec des en-têtes et parfois un corps JSON. La réponse porte un code d'état et, le plus souvent, un corps JSON.

  • 2xx : succès (200 OK, 201 Created).
  • 4xx : erreur du client, la requête est en cause (400 requête invalide, 401 non authentifié, 404 introuvable).
  • 5xx : erreur du serveur, la requête était peut-être correcte (500, 503).

DummyJSON est un service public partagé par toute la classe et par d'autres développeurs. Ses écritures (POST, PUT, DELETE) sont simulées : la réponse ressemble à un succès, mais rien n'est jamais enregistré.

Un seul endroit pour parler au serveur

Durée : 15 min.

fetch est intégré à React Native, comme dans un navigateur. Plutôt que de l'appeler partout, on l'enveloppe dans une seule fonction générique, api<T>(), qui connaît l'URL de base, ajoute les en-têtes et transforme une réponse d'erreur en exception. C'est le rôle que joue une interface Retrofit en Kotlin.

Exemple à lire : fichier src/lib/api.ts (vous le créerez à l'Étape 2)

const BASE_URL = 'https://dummyjson.com';

export class ApiError extends Error {
  constructor(
    public status: number,
    message: string,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

type ApiOptions = RequestInit & { token?: string | null };

export async function api<T>(path: string, options: ApiOptions = {}): Promise<T> {
  const { token, headers, ...rest } = options;
  const res = await fetch(`${BASE_URL}${path}`, {
    ...rest,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...headers,
    },
  });
  if (!res.ok) {
    throw new ApiError(res.status, `HTTP ${res.status} on ${path}`);
  }
  return (await res.json()) as T;
}

À lire dans ce code :

  • BASE_URL est écrit à un seul endroit : les hooks ne passent que le chemin, par exemple /products/1.
  • api<T> est générique : c'est l'appelant qui choisit le type renvoyé, api<ProductPage>('/products') ou api<User>('/auth/me'), comme suspend fun getUser(): User dans une interface Retrofit.
  • Le test if (!res.ok) couvre tous les codes en dehors de 200 à 299.
  • ApiError garde le code HTTP dans status : l'interface peut distinguer un mauvais mot de passe (400), une session expirée (401) et une panne du serveur (500).
  • L'option token ajoute l'en-tête Authorization: Bearer <jeton> seulement quand un jeton est fourni ; ...rest transmet le reste des options (method, body) à fetch.

Pourquoi ? fetch ne rejette sa promesse que sur un échec réseau (pas de connexion, nom de domaine introuvable). Une réponse 404 ou 500 est une réponse normale : la promesse est résolue avec res.ok === false. Sans le test, res.json() lirait le corps d'erreur du serveur et l'écran recevrait un objet qui n'a pas la forme attendue.

as T est une promesse faite au compilateur, pas une vérification à l'exécution : c'est l'équivalent d'un cast non vérifié en Kotlin ou d'un as en Dart sur un Map décodé. Le type TypeScript doit donc refléter le JSON réellement renvoyé par le serveur ; ouvrez la route dans un navigateur pour le vérifier.

Deux sortes d'état

Durée : 15 min.

Jusqu'ici, tout l'état de vos écrans appartenait à l'application : useState pour un champ, SQLite pour les dépenses. Une liste de produits venue de DummyJSON est d'une autre nature : l'application n'en a qu'une copie, qui peut être en retard sur le serveur.

Le réflexe useEffect + fetch

Avec les outils de la séance 01, on écrirait un écran de recherche ainsi : trois états et un effet qui relance la requête quand search change.

const [products, setProducts] = useState<Product[]>([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState<Error | null>(null);

useEffect(() => {
  setLoading(true);
  fetch(`https://dummyjson.com/products/search?q=${search}`)
    .then((res) => res.json())
    .then((data: { products: Product[] }) => setProducts(data.products))
    .catch((e: Error) => setError(e))
    .finally(() => setLoading(false));
}, [search]);

Ce code ne gère pas :

  • les réponses dans le désordre (race condition) : une réponse lente écrase une réponse plus récente ;
  • le cache entre écrans : chaque écran qui se monte refait la même requête ;
  • la déduplication : deux composants qui affichent les mêmes données envoient deux requêtes ;
  • le nouvel essai après un échec passager du réseau ;
  • le rafraîchissement des données devenues anciennes ;
  • le setState appelé après le démontage de l'écran, quand la réponse arrive trop tard.

On peut corriger chaque point à la main, avec un nettoyage dans l'effet, un cache global, des compteurs d'essais. TanStack Query le fait déjà, de la même façon dans tous les écrans.

Réponses dans le désordre

Pourquoi ? TanStack Query range chaque résultat sous sa clé de requête. Une réponse tardive pour ['products', { search: 'ph' }] remplit l'entrée de cache de cette clé ; elle ne peut jamais être affichée par un écran qui lit la clé ['products', { search: 'phone' }].

Quiz éclair

Un écran de recherche utilise useEffect + fetch sans nettoyage. L'utilisateur tape « ph » puis « phone ». La réponse de « phone » arrive en 200 ms, celle de « ph » en 900 ms. Qu'affiche la liste après une seconde ?

Chaque réponse appelle setState à son arrivée : la plus lente, celle de « ph », arrive en dernier et écrase la plus récente. React n'annule aucune requête. Il faut soit un nettoyage dans l'effet qui ignore les réponses obsolètes, soit une clé de requête.

Un cache pour toute l'application

Durée : 20 min.

Le QueryClient est le cache de l'état serveur : il garde chaque résultat sous sa clé, sait quand il a été reçu et quels écrans l'utilisent. Il y en a un seul par application, créé en dehors de tout composant pour qu'un nouveau rendu ne le recrée pas. Le composant QueryClientProvider, placé à la racine, le rend accessible à tous les hooks de TanStack Query. Ce cache vit en mémoire : il disparaît quand l'application est fermée ; le conserver sur disque est le sujet de la séance 05.

Exemple à lire : fichier src/lib/queryClient.ts (vous le créerez à l'Étape 1)

import { QueryClient } from '@tanstack/react-query';

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,
      retry: 2,
    },
  },
});
  • staleTime: 30_000 : une donnée reste fraîche 30 secondes (la valeur par défaut est 0).
  • retry: 2 : après un échec, la requête est retentée deux fois avant de passer en erreur.
  • Ces valeurs par défaut peuvent être remplacées requête par requête.

Anatomie de useQuery

Extrait de src/features/products/useProducts.ts :

export function useProduct(id: string) {
  return useQuery({
    queryKey: ['product', id],
    queryFn: () => api<ProductDetail>(`/products/${id}`),
  });
}
  • queryKey est l'identité de la donnée dans le cache : ['product', '7'] et ['product', '8'] sont deux entrées.
  • queryFn est n'importe quelle fonction qui renvoie une Promise ; ici, l'appel au client api<T>().
  • Le hook renvoie un objet d'état que l'écran lit à chaque rendu ; il n'y a ni useEffect ni useState à écrire.

Aide-mémoire, à consulter pendant les étapes : les champs utilisés aujourd'hui

Champ Signification
data les données en cache, undefined tant qu'il n'y en a pas
isPending aucune donnée en cache encore : premier chargement
isError et error la dernière requête a échoué après les nouveaux essais ; error contient l'exception (par exemple une ApiError)
isFetching une requête est en cours, même en arrière-plan avec des données déjà affichées
isRefetching une requête est en cours alors que des données sont déjà là (rafraîchissement)
refetch fonction qui relance la requête, par exemple pour un bouton « Réessayer »

Les clés de requête

  • Une clé est un tableau. Deux clés sont comparées par valeur, en profondeur, et l'ordre des propriétés d'un objet n'a pas d'importance : { category: 'beauty', search: '' } et { search: '', category: 'beauty' } désignent la même entrée.
  • ['products', { category: 'beauty', search: '' }] et ['products', { category: null, search: '' }] sont deux entrées de cache différentes : changer de filtre, c'est lire une autre entrée.
  • Toute variable utilisée par queryFn doit figurer dans la clé ; sinon deux requêtes différentes partageraient la même entrée.
  • Une clé sert aussi de préfixe pour l'invalidation : ['products'] désigne toutes les entrées dont la clé commence par 'products'.

Fraîcheur : staleTime et gcTime

  • staleTime compte depuis la réception des données. Une donnée périmée n'est pas effacée : elle reste affichée pendant qu'une nouvelle requête part en arrière-plan.
  • gcTime compte depuis le moment où plus aucun écran n'utilise l'entrée. Tant qu'il n'est pas écoulé, revenir sur l'écran affiche les données immédiatement.
  • Les deux durées sont indépendantes : staleTime: Infinity ne garde pas une entrée plus longtemps en mémoire, il empêche seulement de la redemander.
Notion Jetpack Compose (Kotlin) Flutter React Native
État d'une requête ViewModel + StateFlow<UiState> FutureBuilder ou AsyncValue (Riverpod) useQuery : isPending, isError, data
Cache partagé entre écrans Repository + cache écrit à la main Provider ou Riverpod avec cache QueryClient, indexé par clé de requête
Relancer une requête nouvelle collecte ou appel du ViewModel ref.invalidate ou setState refetch ou invalidateQueries

Erreurs fréquentes : L'écran rouge No QueryClient set, use QueryClientProvider to set one signifie qu'un hook de TanStack Query s'exécute en dehors du fournisseur : QueryClientProvider manque dans src/app/_layout.tsx.

Quiz éclair

staleTime vaut 30 s, gcTime vaut 5 min. L'écran catalogue charge les produits, l'utilisateur ouvre un autre onglet, puis revient 2 minutes plus tard (l'écran est remonté). Que voit-il ?

Après staleTime, la donnée est périmée mais toujours en cache : elle est affichée tout de suite, puis revalidée en arrière-plan. Elle n'est supprimée du cache qu'après gcTime sans aucun écran abonné, ici 5 minutes.

Charger page par page avec useInfiniteQuery

Durée : 15 min.

DummyJSON renvoie les produits par pages : limit fixe la taille, skip le nombre de produits à sauter. useInfiniteQuery garde toutes les pages chargées dans une seule entrée de cache et sait calculer le paramètre de la page suivante.

Extrait de src/features/products/useProducts.ts :

export function useProducts(filter: ProductFilter) {
  return useInfiniteQuery({
    queryKey: ['products', filter],
    initialPageParam: 0,
    queryFn: ({ pageParam }) => api<ProductPage>(productsPath(filter, pageParam)),
    getNextPageParam: (last) =>
      last.skip + last.limit < last.total ? last.skip + last.limit : undefined,
  });
}
  • initialPageParam: 0 : la première page commence à skip=0.
  • queryFn reçoit pageParam, ici la valeur de skip de la page à charger.
  • getNextPageParam reçoit la dernière page reçue et renvoie le skip suivant, ou undefined quand il n'y a plus de page.
  • data.pages est un tableau de pages ; l'écran l'aplatit avec flatMap pour obtenir un seul tableau de produits.
  • fetchNextPage() charge la page suivante, hasNextPage dit s'il en reste une, isFetchingNextPage est vrai pendant ce chargement.

C'est le rôle de Paging 3 (LazyPagingItems) avec Compose, ou du package infinite_scroll_pagination avec Flutter, avec un FlatList classique côté affichage.

Écrire avec useMutation

useQuery lit ; useMutation écrit : un POST, un PUT, un DELETE, ou une écriture locale. La mutation ne part pas toute seule : l'écran appelle mutate(variables), par exemple dans un onPress. L'objet renvoyé expose isPending (écriture en cours), isError, isSuccess, et accepte un onSuccess.

Après une écriture réussie, les données lues avant sont fausses. queryClient.invalidateQueries({ queryKey }) marque comme périmée toute requête dont la clé commence par ce préfixe ; celles qu'un écran affiche sont redemandées aussitôt.

Extrait de src/features/cart/useCart.ts (Étape 7) :

export function useAddToCart() {
  const db = useSQLiteContext();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (item: NewCartItem) => cartRepo(db).add(item),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: CART_KEY }),
  });
}
  • mutationFn, comme queryFn, est n'importe quelle fonction asynchrone : ici un appel SQLite au dépôt cartRepo de la séance 02, pas une requête HTTP.
  • onSuccess invalide la clé ['cart'] : l'écran du panier et le compteur de l'onglet relisent la table.
  • useQueryClient() donne accès au QueryClient fourni par QueryClientProvider.

Quiz éclair

Le cache contient ['products', { category: null, search: '' }], ['products', { category: 'beauty', search: '' }] et ['product', '7']. Une mutation appelle invalidateQueries({ queryKey: ['products'] }). Quelles entrées sont marquées périmées ?

L'invalidation compare les clés comme des préfixes de tableau, élément par élément, pas comme du texte. ['product', '7'] commence par l'élément 'product', différent de 'products' : cette entrée n'est pas touchée.

Où vit le jeton de connexion

Durée : 15 min.

DummyJSON authentifie par jeton : après la connexion, chaque requête protégée envoie l'en-tête Authorization: Bearer <jeton>. L'application doit donc garder ce jeton entre deux lancements, et le rendre lisible par tous les hooks qui en ont besoin.

expo-secure-store

  • Trois fonctions asynchrones : setItemAsync(clé, valeur), getItemAsync(clé) (qui renvoie null si la clé n'existe pas) et deleteItemAsync(clé).
  • Les valeurs sont chiffrées par le système : Keystore sur Android, Keychain sur iOS.
  • Uniquement des chaînes, et de petites valeurs : un jeton, pas une liste de produits.
  • Jamais AsyncStorage ni SQLite pour un jeton : ces fichiers ne sont pas chiffrés.
  • Le module fait partie du SDK 57 : il fonctionne dans Expo Go.

React Context

Un Context transmet une valeur à tous les composants d'un sous-arbre sans la passer de props en props.

  • createContext crée le Context ; son Provider, placé dans le layout racine, fournit une value.
  • Les composants la lisent avec useContext, à travers un hook personnalisé useAuth() qui lève une erreur s'il est appelé en dehors du fournisseur : l'oubli se voit tout de suite.
  • Quand la valeur change, tous les composants qui la lisent sont rendus à nouveau. Le Context ne contient donc qu'un petit état qui change rarement (le jeton), jamais les données du serveur : c'est le rôle du QueryClient.

Dans AuthProvider, on retire les appels à SecureStore et on garde seulement useState pour le token. L'utilisateur se connecte, puis ferme complètement l'application et la rouvre. Que se passe-t-il ?

export async function api<T>(path: string, options: ApiOptions = {}): Promise<T> {
  const { token, headers, ...rest } = options;
  const res = await fetch(`${BASE_URL}${path}`, {
    ...rest,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),

    },
  });

  }
  return (await res.json()) as T;
}

import { useInfiniteQuery, useQuery } from '@tanstack/react-query';
import { api } from '@/lib/api';

export type Product = {
  id: number;
  title: string;
  price: number;
  thumbnail: string;
  category: string;
};

export type ProductDetail = Product & {
  description: string;
  rating: number;
  stock: number;
  brand?: string;
};

export type Category = { slug: string; name: string; url: string };

type ProductPage = { products: Product[]; total: number; skip: number; limit: number };

export type ProductFilter = { category: string | null; search: string };

const PAGE_SIZE = 20;

// Set to 1500 to simulate a slow network, then back to 0.
const DEBUG_DELAY_MS = 0;

function productsPath(filter: ProductFilter, skip: number): string {
  const paging = `limit=${PAGE_SIZE}&skip=${skip}`;
  const delay = DEBUG_DELAY_MS > 0 ? `&delay=${DEBUG_DELAY_MS}` : '';
  if (filter.search !== '') {
    return `/products/search?q=${encodeURIComponent(filter.search)}&${paging}${delay}`;
  }
  if (filter.category !== null) {
    return `/products/category/${filter.category}?${paging}${delay}`;
  }
  return `/products?${paging}${delay}`;
}

export function useProducts(filter: ProductFilter) {
  return useInfiniteQuery({
    queryKey: ['products', filter],
    initialPageParam: 0,
    queryFn: ({ pageParam }) => api<ProductPage>(productsPath(filter, pageParam)),
    getNextPageParam: (last) =>
      last.skip + last.limit < last.total ? last.skip + last.limit : undefined,
  });
}

export function useCategories() {
  return useQuery({
    queryKey: ['categories'],
    queryFn: () => api<Category[]>('/products/categories'),
    staleTime: Infinity,
  });
}

export function useProduct(id: string) {
  return useQuery({
    queryKey: ['product', id],
    queryFn: () => api<ProductDetail>(`/products/${id}`),
  });
}

import { useEffect, useState } from 'react';

export function useDebouncedValue<T>(value: T, delayMs: number): T {
  const [debounced, setDebounced] = useState<T>(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(timer);
  }, [value, delayMs]);

  return debounced;
}

import * as SecureStore from 'expo-secure-store';
import { createContext, useContext, useEffect, useState, type ReactNode } from 'react';

const TOKEN_KEY = 'auth_token';

type AuthContextValue = {
  token: string | null;
  isRestoring: boolean;
  signIn: (token: string) => Promise<void>;
  signOut: () => Promise<void>;
};

const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [token, setToken] = useState<string | null>(null);
  const [isRestoring, setIsRestoring] = useState(true);

  useEffect(() => {
    let cancelled = false;
    SecureStore.getItemAsync(TOKEN_KEY)
      .then((stored) => {
        if (!cancelled) setToken(stored);
      })
      .finally(() => {
        if (!cancelled) setIsRestoring(false);
      });
    return () => {
      cancelled = true;
    };
  }, []);

  const signIn = async (newToken: string) => {
    await SecureStore.setItemAsync(TOKEN_KEY, newToken);
    setToken(newToken);
  };

  const signOut = async () => {
    await SecureStore.deleteItemAsync(TOKEN_KEY);
    setToken(null);
  };

  return (
    <AuthContext.Provider value={{ token, isRestoring, signIn, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth(): AuthContextValue {
  const value = useContext(AuthContext);
  if (value === null) {
    throw new Error('useAuth must be used inside <AuthProvider>');
  }
  return value;
}

import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { api, ApiError } from '@/lib/api';
import { useAuth } from './AuthContext';

export type User = {
  id: number;
  username: string;
  email: string;
  firstName: string;
  lastName: string;
  image: string;
};

type LoginResponse = User & { accessToken: string; refreshToken: string };

type Credentials = { username: string; password: string };

export function useLogin() {
  const { signIn } = useAuth();
  return useMutation({
    mutationFn: (credentials: Credentials) =>
      api<LoginResponse>('/auth/login', {
        method: 'POST',
        body: JSON.stringify({ ...credentials, expiresInMins: 60 }),
      }),
    onSuccess: (data) => signIn(data.accessToken),
  });
}

export function useMe() {
  const { token } = useAuth();
  return useQuery({
    queryKey: ['me'],
    queryFn: () => api<User>('/auth/me', { token }),
    enabled: token !== null,
    retry: (failureCount, error) =>
      !(error instanceof ApiError && error.status === 401) && failureCount < 2,
  });
}

export function useLogout() {
  const { signOut } = useAuth();
  const queryClient = useQueryClient();
  return async () => {
    await signOut();
    queryClient.removeQueries({ queryKey: ['me'] });
  };
}

  if (error instanceof ApiError && error.status === 400) {
    return 'Identifiant ou mot de passe incorrect.';
  }
  return 'Connexion impossible. Vérifiez le réseau puis réessayez.';
}

import type { SQLiteDatabase } from 'expo-sqlite';

const DATABASE_VERSION = 1;

export async function migrateDbIfNeeded(db: SQLiteDatabase): Promise<void> {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  let version = row?.user_version ?? 0;
  if (version >= DATABASE_VERSION) return;
  if (version === 0) {
    await db.execAsync(`
      PRAGMA journal_mode = 'wal';
      CREATE TABLE IF NOT EXISTS cart_items (
        product_id INTEGER PRIMARY KEY NOT NULL,
        title TEXT NOT NULL,
        price REAL NOT NULL,
        thumbnail TEXT NOT NULL,
        quantity INTEGER NOT NULL
      );
    `);
    version = 1;
  }
  await db.execAsync(`PRAGMA user_version = ${DATABASE_VERSION}`);
}

import type { SQLiteDatabase } from 'expo-sqlite';

export type CartItem = {
  product_id: number;
  title: string;
  price: number;
  thumbnail: string;
  quantity: number;
};

export type NewCartItem = Omit<CartItem, 'quantity'>;

export const cartRepo = (db: SQLiteDatabase) => ({
  all: () => db.getAllAsync<CartItem>('SELECT * FROM cart_items ORDER BY title'),
  add: (item: NewCartItem) =>
    db.runAsync(
      `INSERT INTO cart_items (product_id, title, price, thumbnail, quantity)
       VALUES (?, ?, ?, ?, 1)
       ON CONFLICT(product_id) DO UPDATE SET quantity = quantity + 1`,
      item.product_id,
      item.title,
      item.price,
      item.thumbnail,
    ),
  remove: (productId: number) =>
    db.runAsync('DELETE FROM cart_items WHERE product_id = ?', productId),
  clear: () => db.runAsync('DELETE FROM cart_items'),
});

import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { useSQLiteContext } from 'expo-sqlite';
import { cartRepo, type NewCartItem } from '@/db/cartRepo';

const CART_KEY = ['cart'] as const;

export function useCart() {
  const db = useSQLiteContext();
  const query = useQuery({
    queryKey: CART_KEY,
    queryFn: () => cartRepo(db).all(),
    staleTime: Infinity,
  });
  const items = query.data ?? [];
  const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  const count = items.reduce((sum, item) => sum + item.quantity, 0);
  return { items, total, count, isPending: query.isPending };
}

export function useAddToCart() {
  const db = useSQLiteContext();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (item: NewCartItem) => cartRepo(db).add(item),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: CART_KEY }),
  });
}

export function useRemoveFromCart() {
  const db = useSQLiteContext();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (productId: number) => cartRepo(db).remove(productId),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: CART_KEY }),
  });
}

À retenir

Pourquoi ? TanStack Query n'est pas lié à HTTP : le dépôt SQLite est une source asynchrone comme une autre, et l'invalidation met à jour en même temps le compteur de l'onglet et l'écran du panier, sans useState partagé. Le panier survit au redémarrage parce qu'il est sur le disque ; le cache des produits, lui, est en mémoire seulement (séance 05).

Erreurs fréquentes : Une erreur de useSQLiteContext signifie que SQLiteProvider manque ou se trouve sous un écran qui utilise le panier. no such table: cart_items signifie que la base a été créée par une version antérieure de migrations.ts : changez databaseName (par exemple shop2.db) dans src/app/_layout.tsx.
