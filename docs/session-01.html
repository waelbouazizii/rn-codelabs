Prérequis & objectifs

Objectif

Vous connaissez Kotlin avec Jetpack Compose et Dart avec Flutter. Cette séance transpose ce que vous savez vers TypeScript et React, puis construit Profile & Contacts : une application à deux onglets, une liste de contacts typés et une fiche de détail, testée sur votre téléphone avec Expo Go.

Ouvrez Expo Go sur votre téléphone, installé depuis le store, et lisez la version de SDK qu'il prend en charge.   5. décrire le routage par fichiers d'Expo Router : src/app, _layout.tsx, groupe (tabs), route dynamique [id].tsx.

Où se place cette séance

Durée : 12 min.

Expo Go et Metro

Une application React Native a deux parties : votre JavaScript, et du code natif (Kotlin, Swift) qui dessine les vues et donne accès à l'appareil. Expo Go est une application déjà compilée qui contient la partie native d'Expo SDK 57. Votre PC ne compile rien : Metro assemble votre JavaScript et Expo Go le télécharge par le Wi-Fi.

Conséquence : dans Expo Go, vous pouvez changer tout le JavaScript, mais vous ne pouvez pas ajouter de code natif. Une bibliothèque qui apporte son propre code natif demande un development build, c'est-à-dire votre propre application native compilée. Ce cours reste entièrement dans Expo Go ; les development builds sont présentés en séance 07, en théorie seulement.

Notion Projet Kotlin (Compose) Flutter React Native avec Expo Go
Ce qui est compilé à chaque lancement APK complet avec Gradle application native avec flutter run rien : seul le JavaScript est assemblé par Metro
Mise à jour pendant le développement Live Edit Hot Reload Fast Refresh
Ajouter une bibliothèque avec du code natif possible possible impossible dans Expo Go (development build nécessaire)

Dépendance au SDK : la liste des modules natifs d'Expo Go change avec chaque SDK. Cette page est écrite pour le SDK 57.

Quiz éclair

Vous ajoutez avec npm une bibliothèque qui contient son propre code natif Kotlin et Swift, absent d'Expo Go. Que se passe-t-il quand votre écran appelle cette bibliothèque dans Expo Go ?

Expo Go est déjà compilé : il ne peut exécuter que les modules natifs qu'il contient. npm ne télécharge que des fichiers ; rien ne recompile la partie native. Pour une telle bibliothèque, il faut un development build.

Ce qui change par rapport à Kotlin et Dart

Durée : 20 min.

TypeScript est du JavaScript avec des types vérifiés avant l'exécution. Deux différences comptent pour vous. Le typage est structurel : deux types qui ont les mêmes champs sont compatibles, même sans lien d'héritage. Et les types disparaissent à l'exécution : Metro les retire sans les vérifier.

Une erreur de type n'empêche pas l'application de s'afficher dans Expo Go. Seule la commande npx tsc --noEmit vérifie les types. Elle doit passer sans erreur avant chaque commit, et elle fait partie de la note.

Notion Kotlin Dart TypeScript
Forme d'un objet data class Contact(val id: String) class Contact { final String id; } type Contact = { id: string }
Valeur absente String? String? string | undefined, ou champ email?: string
Accès sûr contact?.email contact?.email contact?.email
Valeur par défaut email ?: "aucun" email ?? 'aucun' email ?? 'aucun'
Choix fermé de valeurs enum class Role { STUDENT, TEACHER } enum Role { student, teacher } type Role = 'student' | 'teacher'
Liste typée List<Contact> List<Contact> Contact[]
Fonction générique fun <T> first(xs: List<T>): T? T? first<T>(List<T> xs) function first<T>(xs: T[]): T | undefined
Référence non réassignable val final const

type ou interface ? Les deux décrivent la forme d'un objet. Une interface peut être étendue et fusionnée ; un type peut aussi décrire une union. Dans ce cours, nous écrivons type partout, y compris type Props pour les props d'un composant.

Code annoté

Exemple à lire (TypeScript) :

type ContactRole = 'student' | 'teacher' | 'staff';

type Contact = {
  id: string;
  name: string;
  role: ContactRole;
  email?: string;
};

const contacts: Contact[] = [
  { id: '1', name: 'Amira', role: 'student' },
  { id: '2', name: 'Karim', role: 'teacher', email: 'karim@example.com' },
];

// Generic function: works for any type that has a string id.
function findById<T extends { id: string }>(items: T[], id: string): T | undefined {
  return items.find((item) => item.id === id);
}

// found has the type Contact | undefined: strict null checks force a test.
const found = findById(contacts, '3');

// Optional chaining stops at the first undefined, ?? gives the default value.
const emailLength: number = found?.email?.length ?? 0;

// The union is closed: tsc reports an error if a case is missing.
function roleLabel(role: ContactRole): string {
  switch (role) {
    case 'student':
      return 'Étudiant';
    case 'teacher':
      return 'Enseignant';
    case 'staff':
      return 'Administration';
  }
}

console.log(emailLength, roleLabel('staff'));

À lire dans ce code :

  • L'union 'student' | 'teacher' | 'staff' joue le rôle d'une enum class : toute autre chaîne est refusée par tsc.
  • email?: string signifie string | undefined. Il n'existe pas de null implicite.
  • find renvoie T | undefined : il faut tester le résultat avant de l'utiliser, comme un type nullable en Kotlin.

Quiz éclair

En mode strict, que répond npx tsc --noEmit pour ces deux lignes ?

const found = contacts.find((c) => c.id === '3');
console.log(found.name);

find renvoie Contact | undefined. Le contrôle strict refuse l'accès direct ; il faut un test (if (found)) ou un accès sûr (found?.name). L'accès sûr n'est jamais automatique.

Un composant est une fonction

Durée : 23 min.

Un composant React est une fonction TypeScript qui reçoit des props et renvoie du JSX. React rappelle cette fonction à chaque fois que son état ou ses props changent : c'est le rendu, l'équivalent d'une recomposition en Compose ou d'un appel à build() en Flutter.

Notion Jetpack Compose Flutter React Native
Composant @Composable fun ContactRow(contact: Contact) class ContactRow extends StatelessWidget function ContactRow({ contact }: Props)
Paramètres paramètres de la fonction champs du constructeur props décrites par type Props
État local remember { mutableStateOf(0) } setState(() => count++) const [count, setCount] = useState(0)
Nouveau rendu recomposition build() la fonction composant est rappelée
Remonter un événement onClick: () -> Unit VoidCallback onTap prop onPress: () => void
Mise en page Column, Row Column, Row View avec flexDirection (colonne par défaut)
Liste longue LazyColumn ListView.builder FlatList (data, renderItem, keyExtractor)

Règles du JSX :

  • Un composant renvoie un seul élément racine.
  • Les accolades insèrent une expression TypeScript : {contact.name}.
  • Tout texte est dans un composant Text ; une chaîne placée directement dans un View provoque une erreur.
  • Un nom de composant commence par une majuscule ; les styles sont des objets créés avec StyleSheet.create.
  • Une condition s'écrit avec l'opérateur ternaire ; il n'y a pas de if dans le JSX.

Le cycle de rendu

Flux de données à sens unique. Les props descendent du parent vers l'enfant et sont en lecture seule. Pour modifier une donnée du parent, l'enfant appelle une fonction reçue en prop. C'est le même principe que le state hoisting en Compose.

Code annoté

Exemple à lire (TypeScript) :

import { useState } from 'react';
import { Pressable, Text, View } from 'react-native';

type Props = {
  label: string;
  step?: number;
};

export function Counter({ label, step = 1 }: Props) {
  const [count, setCount] = useState<number>(0);

  const handlePress = () => {
    setCount(count + step);
    // count still holds the value of the current render here.
    console.log(count);
  };

  return (
    <View>
      <Text>
        {label} : {count}
      </Text>
      <Pressable onPress={handlePress}>
        <Text>Ajouter {step}</Text>
      </Pressable>
    </View>
  );
}

Idée fausse fréquente

setCount ne fonctionne pas comme une affectation. Dans handlePress, console.log(count) affiche l'ancienne valeur. Quand la nouvelle valeur dépend de l'ancienne, passez une fonction : setCount((value) => value + step).

Quiz éclair

count vaut 0. Un gestionnaire onPress exécute deux fois de suite setCount(count + 1). Après le rendu suivant, que vaut count ?

Pendant ce rendu, count vaut 0 pour les deux appels : chacun demande la valeur 1. Avec la forme fonctionnelle setCount((value) => value + 1), appelée deux fois, le résultat serait 2.

Synchroniser avec l'extérieur

Durée : 18 min.

useEffect exécute du code après le rendu, pour synchroniser le composant avec quelque chose d'extérieur à React : un minuteur, un abonnement, plus tard une base de données ou un broker. Ce n'est pas un onCreate : l'effet peut s'exécuter plusieurs fois, et il n'est pas fait pour calculer une valeur à afficher ni pour réagir à un appui.

Notion Jetpack Compose Flutter React Native
Lancer après l'affichage LaunchedEffect(key) { start() } initState() useEffect(() => { start(); }, [key])
Relancer quand une valeur change la clé de LaunchedEffect change didUpdateWidget() une valeur du tableau de dépendances change
Nettoyer DisposableEffect(key) { onDispose { stop() } } dispose() la fonction renvoyée par l'effet
Une seule fois LaunchedEffect(Unit) initState() tableau de dépendances vide []

Aide-mémoire, à consulter pendant les étapes :

Deuxième argument L'effet s'exécute
absent après chaque rendu
[] après le premier rendu seulement ; nettoyage quand le composant disparaît
[a, b] après le premier rendu, puis après chaque rendu où a ou b a changé ; le nettoyage de l'ancien effet passe avant le nouvel effet

Code annoté

Exemple à lire (TypeScript) :

import { useEffect, useState } from 'react';
import { Text } from 'react-native';

type Props = {
  contactId: string;
};

export function OnlineTimer({ contactId }: Props) {
  const [seconds, setSeconds] = useState<number>(0);

  useEffect(() => {
    console.log(`start timer for ${contactId}`);
    const timer = setInterval(() => {
      setSeconds((value) => value + 1);
    }, 1000);

    // Cleanup: runs before the next effect and when the component disappears.
    return () => {
      console.log(`stop timer for ${contactId}`);
      clearInterval(timer);
    };
  }, [contactId]);

  return <Text>En ligne depuis {seconds} s</Text>;
}

Règles des hooks

React reconnaît chaque hook par son ordre d'appel, comme Compose reconnaît un remember par sa position dans la fonction. Deux règles en découlent.

  • Appeler les hooks au premier niveau du composant : jamais dans un if, une boucle, ni après un return anticipé.
  • Appeler les hooks uniquement dans un composant ou dans une fonction dont le nom commence par use.

Interdit :

if (contact) {
  const [isFavorite, setIsFavorite] = useState(false);
}

Erreurs fréquentes : Un hook appelé après un return anticipé peut provoquer l'écran rouge Rendered more hooks than during the previous render. : le nombre de hooks a changé entre deux rendus. Placez tous les hooks avant le premier return.

Dépendance au SDK : le modèle du SDK 57 active React Compiler, qui mémorise les calculs à votre place. N'écrivez ni useMemo ni useCallback dans ce cours.

Quiz éclair

Un composant contient useEffect(() => { console.log('effect'); }) sans tableau de dépendances. L'écran s'ouvre, puis l'utilisateur appuie trois fois sur un bouton qui modifie l'état du composant. Combien de fois « effect » s'affiche-t-il au total ?

Sans deuxième argument, l'effet s'exécute après chaque rendu. Pour une seule exécution, il faut un tableau vide [] ; pour dépendre d'une valeur, il faut la lister dans le tableau.

Un fichier, une route

Durée : 12 min.

Avec Expo Router, vous ne déclarez pas les routes dans un fichier central : chaque fichier de src/app est un écran, et son chemin donne son URL. Un fichier _layout.tsx décrit le conteneur de navigation de son dossier (pile ou onglets). Un dossier entre parenthèses regroupe des écrans sans apparaître dans l'URL. Un nom entre crochets est un paramètre.

Aide-mémoire, à consulter pendant les étapes :

src/app/(tabs)/_layout.tsx aucune barre d'onglets (Tabs)
src/app/(tabs)/index.tsx / onglet Profil
src/app/(tabs)/contacts.tsx /contacts onglet Contacts
src/app/contact/[id].tsx /contact/3 fiche d'un contact, id vaut "3"
Notion Jetpack Compose Flutter React Native (Expo Router)
Déclarer une route composable("contact/{id}") dans un NavHost GoRoute(path: '/contact/:id') le fichier src/app/contact/[id].tsx
Naviguer navController.navigate("contact/3") context.push('/contact/3') composant Link avec href
Lire le paramètre backStackEntry.arguments?.getString("id") state.pathParameters['id'] useLocalSearchParams<{ id: string }>()
Onglets NavigationBar et NavHost StatefulShellRoute dossier (tabs) et composant Tabs

Un paramètre de route vient d'une URL : c'est toujours une chaîne. C'est pour cela que l'identifiant d'un contact est de type string dans l'atelier.

Dépendance au SDK : cette page décrit Expo Router tel qu'il est livré avec le SDK 57. Le SDK 58 remanie le cœur du routeur ; les imports seront revérifiés à ce moment-là.

import { FlatList, StyleSheet, Text, View } from 'react-native';

  return <View style={styles.separator} />;

export default function ContactsScreen() {

Pourquoi ? L'état est placé dans le parent qui en a besoin pour le compteur, et descend vers ContactRow par isFavorite ; l'enfant remonte l'intention par onToggleFavorite. C'est le state hoisting de Compose. Le tableau n'est jamais modifié sur place : filter et la syntaxe [...current, id] créent un nouveau tableau, et c'est ce changement de référence que React détecte. L'effet s'exécute après le rendu, à l'ouverture puis à chaque nouvelle valeur de favoriteIds.

Erreurs fréquentes : Avec current.push(id), le tableau garde la même référence : React ne voit aucun changement et l'écran ne se met pas à jour, sans message d'erreur. Sans la prop extraData, FlatList ne redessine pas les lignes quand seuls les favoris changent. Si vous fermez puis rouvrez l'application, les favoris sont perdus : l'état vit en mémoire.   • Le dossier example n'existe pas.

Objectif

Durée : 10 min. Remettre l'application : un README avec une capture d'écran du téléphone et la sortie d'expo-doctor, un commit, et le tag s1-submit poussé sur GitHub. Date limite : jeudi 23:59 après la séance. C'est le tag qui est noté.

Commandes

Le serveur du Terminal 1 peut rester lancé. Dans le Terminal 2 (dossier s1-profile-contacts), lancez les deux vérifications et gardez la sortie de la seconde.

Terminal 2 — Bash et PowerShell (identique) :

npx tsc --noEmit
npx expo-doctor@latest

Seulement si expo-doctor signale des versions de paquets incompatibles avec le SDK — Bash et PowerShell (identique) :

npx expo install --fix

Sur le téléphone, faites une capture d'écran de l'onglet Contacts avec au moins un favori. Copiez l'image sur le PC dans s1-profile-contacts/screenshots/s1-phone.png. Remplacez ensuite le contenu de README.md (dans s1-profile-contacts) par le modèle de la carte suivante, complétez-le et enregistrez.

Enregistrez et publiez, puis posez le tag.

Terminal 2 — Bash et PowerShell (identique) :

git add .
git commit -m "Add s1-profile-contacts"
git push
git tag s1-submit
git push origin s1-submit

À retenir

Pourquoi ? Le correcteur clone votre dépôt au tag s1-submit, lance npm install puis npx expo start, et scanne le QR code. Tout ce qui n'est pas dans le commit du tag n'existe pas pour lui. Le dossier node_modules n'est pas versionné : il est recréé par npm install.

Erreurs fréquentes : Un tag posé avant le dernier commit ne contient pas vos dernières modifications. Si vous corrigez après coup, refaites un commit, puis déplacez le tag avec git tag -f s1-submit et git push -f origin s1-submit, avant la date limite.
