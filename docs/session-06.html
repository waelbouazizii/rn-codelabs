Prérequis & objectifs

Objectif

Vos applications lisent déjà une base locale (séance 02), une API REST (séance 03), Firestore en temps réel (séance 04), et survivent à la perte du réseau (séance 05). Cette séance branche l'application sur un objet connecté. Un ESP32 simulé dans Wokwi mesure la température et l'humidité, publie une mesure toutes les 5 secondes et allume une LED à la demande. Vous construisez IoT Dashboard : la mesure en direct, un badge En ligne / Hors ligne, un bouton qui pilote la LED et attend la réponse de l'appareil, et un historique gardé dans SQLite. Vous n'écrivez pas de code électronique : l'appareil vous est fourni, vous consommez son contrat de messages, comme vous avez consommé l'API de DummyJSON. Tout tourne dans Expo Go.

Avant la séance

Ouvrez Expo Go sur votre téléphone, installé depuis le store, et lisez la version de SDK qu'il prend en charge. Elle doit correspondre au SDK utilisé sur cette page : SDK 57, avec --template default@sdk-57. Sur iPhone, seule la version de l'App Store fonctionne : en cas d'écart, attendez la mise à jour de la page au lieu d'installer une autre version d'Expo Go. Vérifiez aussi que npx expo whoami et Expo Go affichent le même compte Expo. Enfin, ouvrez https://wokwi.com/projects/481765321571531777 dans le navigateur du PC : le projet doit se charger et montrer l'ESP32, le capteur DHT22 et la LED. Un compte Wokwi n'est pas obligatoire, mais il permet d'enregistrer votre projet.

À la fin de la séance, vous savez

  1. distinguer requête/réponse (REST), écouteur temps réel (Firestore) et publication/abonnement (MQTT), et choisir selon le besoin ;

Le vocabulaire

Broker
Le serveur central. Chaque client ouvre une seule connexion vers lui ; les clients ne se parlent jamais directement. Ici, le broker public de HiveMQ.
Client et client ID
Tout programme connecté au broker : l'ESP32 et votre application sont deux clients. Chaque client se présente avec un identifiant ; si un second client arrive avec le même identifiant, le broker ferme la connexion du premier.
Topic
Une adresse hiérarchique, en texte, découpée par des barres obliques : iset/iam2/prenom-nom/sensors. Un topic n'a pas besoin d'être créé : il existe dès qu'on y publie. Les majuscules comptent.
Message (payload)
Les octets publiés sur un topic. MQTT ne leur impose aucun format : l'appareil envoie du texte (online, on) ou du JSON.
Abonnement
Un client demande au broker de lui transmettre les messages de certains topics. Un abonnement peut utiliser des jokers.

Jokers d'abonnement

Les jokers ne servent qu'à s'abonner, jamais à publier. + remplace exactement un niveau ; # remplace tous les niveaux restants et ne peut être que le dernier caractère du filtre.

Filtre Reçoit Ne reçoit pas
iset/iam2/+/status iset/iam2/sami/status ; iset/iam2/lina/status iset/iam2/sami/cmd/led ; iset/iam2/status
iset/iam2/sami/# iset/iam2/sami/sensors ; iset/iam2/sami/cmd/led ; iset/iam2/sami iset/iam2/lina/sensors
iset/iam2/sami/+/led iset/iam2/sami/cmd/led ; iset/iam2/sami/state/led iset/iam2/sami/status

Pourquoi ? Le préfixe iset/iam2/prenom-nom/ range les topics de chaque étudiant dans sa propre branche. L'enseignant peut ainsi suivre toute la classe avec un seul abonnement iset/iam2/+/status, et chaque application ne reçoit que les messages de son appareil.

Topic (après iset/iam2/prenom-nom/) Sens Contenu Retenu QoS de publication

Objectif

Durée : 20 min.

Prévoir ce que reçoit un abonné selon la QoS, le drapeau retain et le testament de l'appareil.

Qualité de service (QoS)

Niveau Garantie Mécanisme Dans l'atelier
QoS 0 Au plus une fois : le message peut se perdre. Envoi sans accusé de réception. Mesures du capteur : la suivante arrive 5 s plus tard.
QoS 1 Au moins une fois : le message peut arriver en double. Le récepteur répond PUBACK ; sans PUBACK, l'émetteur renvoie. Commande de la LED, abonnements de l'application.
QoS 2 Exactement une fois. Échange en quatre messages, plus lent. Non utilisé (la bibliothèque de l'ESP32 ne publie qu'en QoS 0).

La QoS vaut pour un trajet : de l'émetteur au broker, puis du broker à chaque abonné. Un abonné reçoit au niveau le plus bas entre la QoS de publication et celle de son abonnement : une mesure publiée en QoS 0 lui arrive en QoS 0, même s'il s'est abonné en QoS 1.

Messages retenus et testament

Message retenu (retain)
Le broker garde le dernier message retenu de chaque topic et l'envoie aussitôt à tout nouvel abonné. L'appareil retient status et state/led : votre application connaît l'état de l'appareil et de la LED dès qu'elle se connecte. Les mesures ne sont pas retenues : une vieille mesure ressemblerait à une mesure actuelle. Les commandes non plus : une commande retenue serait rejouée à chaque redémarrage de l'appareil.
Testament (Last Will and Testament, LWT)
Un message que le client confie au broker au moment de la connexion. Si la connexion disparaît sans déconnexion propre (réseau coupé, plantage, onglet Wokwi fermé), le broker le publie à sa place. L'appareil déclare le testament offline, retenu, sur status, puis publie lui-même online, retenu, une fois connecté.
Keep-alive
Le client promet de donner signe de vie au moins toutes les N secondes (un ping s'il n'a rien à publier). Sans nouvelles pendant une fois et demie ce délai, le broker considère le client comme perdu et publie son testament. L'ESP32 utilise 15 s, l'application 30 s.
Session propre (clean session)
Avec clean: true, le broker oublie les abonnements du client à chaque déconnexion. L'application se réabonne donc à chaque connexion, dans l'événement connect. Une session persistante (clean: false et identifiant fixe) garderait les messages QoS 1 manqués, ce dont ce tableau de bord n'a pas besoin.

Chronologie

Quiz éclair

L'appareil a publié online (retenu) sur status, puis sa connexion a été coupée sans déconnexion propre. Une minute plus tard, une nouvelle application s'abonne à status. Que reçoit-elle immédiatement ?

Le broker a publié le testament offline, retenu, au nom de l'appareil : il remplace online comme dernier message retenu du topic. Un message retenu ne dépend pas de la présence de son émetteur ; il ne disparaît que si quelqu'un publie un message retenu vide sur le topic.

L'application publie on sur cmd/led en QoS 1. L'accusé PUBACK du broker se perd, et MQTT.js renvoie le message. Que peut constater l'appareil, abonné en QoS 1 ?

QoS 1 garantit au moins une livraison, pas une seule : un renvoi peut créer un doublon. Une commande on/off est idempotente (l'appliquer deux fois donne le même résultat), contrairement à une commande « inverser l'état ». C'est une raison de publier on ou off plutôt que toggle.

Deux transports, un broker

MQTT fonctionne normalement sur une connexion TCP, port 1883 (8883 avec TLS). L'ESP32 l'utilise. Expo Go, lui, contient un ensemble fixe de modules natifs : votre JavaScript ne peut pas ouvrir de socket TCP brut, mais React Native fournit WebSocket. MQTT.js choisit donc MQTT dans des trames WebSocket, sur une connexion chiffrée wss://. Le broker accepte les deux transports et relaie les messages de l'un à l'autre.

Dans l'application, n'écrivez jamais une URL mqtt ou tcp ni le port 1883 : Expo Go ne peut pas les ouvrir et la connexion reste bloquée sur « Connexion en cours ». Seules les URL wss:// fonctionnent. Le port et le chemin (8884, /mqtt) sont propres à chaque broker.

Notion Compose Flutter React Native
Bibliothèque MQTT HiveMQ MQTT Client ou Eclipse Paho (Java/Kotlin) mqtt_client (Dart) MQTT.js (paquet mqtt)
Transport possible TCP ou WebSocket TCP ou WebSocket ; WebSocket seulement sur le Web WebSocket seulement dans Expo Go (wss://)

Garder le client entre deux affichages Propriété du ViewModel Champ de la classe State useRef
Messages vers l'interface StateFlow collecté par l'écran setState ou Stream useState dans un hook personnalisé

Pourquoi ? En Kotlin ou en Dart, vous pourriez ouvrir TCP sur 1883 directement. En React Native aussi, mais seulement avec une bibliothèque native dans un development build, interdit en atelier. Rester sur WebSocket garde l'application compatible avec Expo Go, sans changer le reste du code.

useRef, nouveau dans ce cours

useRef garde une valeur d'un affichage à l'autre, comme useState, mais modifier ref.current ne déclenche pas de nouvel affichage. C'est l'équivalent d'une propriété d'un ViewModel ou d'un champ de la classe State en Flutter. Le hook s'en sert deux fois : pour garder le client MQTT, qui n'a rien à afficher, et pour garder la dernière version de la fonction onMessage.

Fichier src/lib/useMqtt.ts :

import mqtt, { type MqttClient } from 'mqtt';
import { useEffect, useRef, useState } from 'react';

export type ConnectionStatus = 'connecting' | 'connected' | 'reconnecting' | 'offline';

type UseMqttOptions = {
  url: string;
  // Pass an array declared outside the component: it must stay the same between renders.
  topics: readonly string[];
  onMessage: (topic: string, payload: string) => void;
};

export function useMqtt({ url, topics, onMessage }: UseMqttOptions) {
  // A ref keeps a value between renders; changing it does not trigger a render.
  const clientRef = useRef<MqttClient | null>(null);
  const onMessageRef = useRef(onMessage);
  const [status, setStatus] = useState<ConnectionStatus>('connecting');

  // After every render, remember the latest onMessage without reconnecting.
  useEffect(() => {
    onMessageRef.current = onMessage;
  });

  useEffect(() => {
    const client = mqtt.connect(url, {
      clientId: `iam2-app-${Math.random().toString(16).slice(2, 10)}`,
      clean: true,
      keepalive: 30,
      reconnectPeriod: 2000,
      connectTimeout: 10_000,
    });
    clientRef.current = client;

    client.on('connect', () => {
      setStatus('connected');
      client.subscribe([...topics], { qos: 1 });
    });
    client.on('reconnect', () => setStatus('reconnecting'));
    client.on('offline', () => setStatus('offline'));
    client.on('error', (error) => console.warn(`[mqtt] ${error.message}`));
    client.on('message', (topic, payload) => {
      onMessageRef.current(topic, payload.toString());
    });

    // Cleanup: close the connection when the component unmounts.
    return () => {
      clientRef.current = null;
      client.end(true);
    };
  }, [url, topics]);

  const publish = (topic: string, message: string) => {
    clientRef.current?.publish(topic, message, { qos: 1, retain: false });
  };

  return { status, publish };
}

Ce qu'il faut comprendre

  1. mqtt.connect(url, options) ouvre la connexion et renvoie aussitôt un client ; la connexion s'établit ensuite en arrière-plan et le client émet des événements : connect, reconnect, offline, error, message. Chaque événement met à jour status, ce qui réaffiche l'écran.
  2. L'identifiant iam2-app- suivi de caractères aléatoires est différent à chaque connexion : deux téléphones, ou deux rechargements, ne se chassent pas l'un l'autre du broker.
  3. reconnectPeriod: 2000 : après une coupure, MQTT.js retente toutes les 2 secondes, sans code de votre part. Avec clean: true, le broker oublie les abonnements ; c'est pourquoi subscribe est appelé dans l'événement connect, qui se produit aussi après chaque reconnexion.
  4. Les dépendances de l'effet sont [url, topics] : si l'une change, React exécute le nettoyage puis rouvre une connexion. Le tableau topics doit donc être le même d'un affichage à l'autre : déclarez-le hors du composant (SUBSCRIPTIONS dans useDevice).
  5. onMessage n'est pas une dépendance : on ne veut pas se reconnecter chaque fois que le composant passe une nouvelle fonction. Le premier effet, sans tableau de dépendances, range la dernière version dans onMessageRef après chaque affichage ; l'écouteur message appelle toujours onMessageRef.current, donc la version la plus récente.
  6. Le nettoyage appelle client.end(true) : la connexion est fermée quand l'écran disparaît, et à chaque Fast Refresh qui réexécute l'effet. Sans lui, chaque rechargement ajouterait un client qui reste connecté et reçoit les mêmes messages.
  7. publish envoie en QoS 1, sans retain : c'est le bon réglage pour une commande. payload arrive sous forme d'octets (Buffer) ; toString() les convertit en texte.

Pourquoi ? Un effet capture les valeurs de l'affichage où il s'est exécuté. Si l'écouteur appelait directement le onMessage du premier affichage, il travaillerait avec des valeurs figées : c'est une « fermeture périmée » (stale closure). La ref donne à un écouteur de longue durée l'accès à la version actuelle, sans rouvrir la connexion.

Quiz éclair

Vous supprimez la fonction de nettoyage (le return avec client.end) de l'effet de connexion, puis vous enregistrez useMqtt.ts trois fois de suite pendant que l'application tourne. Que se passe-t-il ?

React ne sait pas fermer une connexion qu'il n'a pas créée : c'est le rôle de la fonction de nettoyage. Sans elle, les anciens clients restent connectés au broker, se reconnectent seuls et appellent encore le code de messages. On voit alors des doublons dans le terminal et des connexions fantômes.

#include <WiFi.h>
#include <PubSubClient.h>
#include <DHT.h>

// The only line to change: the same value as STUDENT_ID in src/lib/config.ts.
const char* STUDENT_ID = "prenom-nom";

const char* WIFI_SSID = "Wokwi-GUEST";
const char* MQTT_HOST = "broker.hivemq.com";
const int MQTT_PORT = 1883;
const int DHT_PIN = 15;
const int LED_PIN = 2;
const unsigned long PUBLISH_EVERY_MS = 5000;

WiFiClient net;
PubSubClient mqttClient(net);
DHT dht(DHT_PIN, DHT22);
unsigned long lastPublish = 0;
bool ledOn = false;

String topic(const char* suffix) {
  return String("iset/iam2/") + STUDENT_ID + "/" + suffix;
}

void publishLedState() {
  // Retained: an app that connects later receives the current LED state at once.
  mqttClient.publish(topic("state/led").c_str(), ledOn ? "on" : "off", true);
}

void onMessage(char* receivedTopic, byte* payload, unsigned int length) {
  String message;
  for (unsigned int i = 0; i < length; i++) {
    message += (char)payload[i];
  }
  if (String(receivedTopic) == topic("cmd/led") && (message == "on" || message == "off")) {
    ledOn = message == "on";
    digitalWrite(LED_PIN, ledOn ? HIGH : LOW);
    publishLedState();
    Serial.println("LED " + message);
  }
}

void connectMqtt() {
  while (!mqttClient.connected()) {
    String clientId = String("esp32-") + STUDENT_ID;
    // Last Will: if the connection drops, the broker publishes "offline" (retained) for us.
    if (mqttClient.connect(clientId.c_str(), topic("status").c_str(), 1, true, "offline")) {
      mqttClient.publish(topic("status").c_str(), "online", true);
      mqttClient.subscribe(topic("cmd/led").c_str(), 1);
      publishLedState();
      Serial.println("MQTT connected as " + clientId);
    } else {
      Serial.print("MQTT connection failed, state ");
      Serial.println(mqttClient.state());
      delay(2000);
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);
  dht.begin();

  WiFi.begin(WIFI_SSID, "", 6);
  while (WiFi.status() != WL_CONNECTED) {
    delay(250);
  }
  Serial.println("WiFi connected");

  mqttClient.setServer(MQTT_HOST, MQTT_PORT);
  mqttClient.setCallback(onMessage);
}

void loop() {
  if (!mqttClient.connected()) {
    connectMqtt();
  }
  mqttClient.loop();

  if (millis() - lastPublish >= PUBLISH_EVERY_MS) {
    lastPublish = millis();
    float t = dht.readTemperature();
    float h = dht.readHumidity();
    if (!isnan(t) && !isnan(h)) {
      // ts: seconds since the device started (the device has no clock).
      String json = "{\"t\":" + String(t, 1) + ",\"h\":" + String(h, 1) + ",\"ts\":" + String(millis() / 1000) + "}";
      mqttClient.publish(topic("sensors").c_str(), json.c_str());
      Serial.println("Published " + json);
    }
  }
  delay(10);
}

export type Reading = {
  t: number;
  h: number;
  receivedAt: number;
};

export type DeviceStatus = 'unknown' | 'online' | 'offline';
export type LedState = 'unknown' | 'on' | 'off';

// The payload comes from the network: check every field before trusting it.
export function parseReading(payload: string, receivedAt: number): Reading | null {
  try {
    const data: unknown = JSON.parse(payload);
    if (
      typeof data === 'object' &&
      data !== null &&
      't' in data &&
      'h' in data &&
      typeof data.t === 'number' &&
      typeof data.h === 'number'
    ) {
      return { t: data.t, h: data.h, receivedAt };
    }
    return null;
  } catch {
    return null;
  }
}

export function parseDeviceStatus(payload: string): DeviceStatus {
  return payload === 'online' || payload === 'offline' ? payload : 'unknown';
}

  const [deviceStatus, setDeviceStatus] = useState<DeviceStatus>('unknown');

      }
    },

import { useEffect, useState } from 'react';

import { parseDeviceStatus, parseReading, type DeviceStatus, type LedState, type Reading } from '@/features/device/reading';
import { MQTT_URL, TOPICS } from '@/lib/config';
import { useMqtt } from '@/lib/useMqtt';

// Declared once, outside the hook: the same array on every render.
const SUBSCRIPTIONS = [TOPICS.sensors, TOPICS.status, TOPICS.ledState];
const ACK_TIMEOUT_MS = 5000;

export function useDevice() {
  const [reading, setReading] = useState<Reading | null>(null);
  const [deviceStatus, setDeviceStatus] = useState<DeviceStatus>('unknown');
  const [led, setLed] = useState<LedState>('unknown');
  const [pendingLed, setPendingLed] = useState<'on' | 'off' | null>(null);
  const [ledError, setLedError] = useState<string | null>(null);

  const { status: connection, publish } = useMqtt({
    url: MQTT_URL,
    topics: SUBSCRIPTIONS,
    onMessage: (topic, payload) => {
      if (topic === TOPICS.sensors) {
        const next = parseReading(payload, Date.now());
        if (next) {
          setReading(next);
        } else {
          console.warn(`[mqtt] ignored payload: ${payload}`);
        }
      } else if (topic === TOPICS.status) {
        setDeviceStatus(parseDeviceStatus(payload));
      } else if (topic === TOPICS.ledState && (payload === 'on' || payload === 'off')) {
        // The device's acknowledgement is the only source of truth for the LED.
        setLed(payload);
        setPendingLed(null);
      }
    },
  });

  // No acknowledgement after 5 seconds: give the button back and explain why.
  useEffect(() => {
    if (pendingLed === null) {
      return;
    }
    const timer = setTimeout(() => {
      setPendingLed(null);
      setLedError("Pas de réponse de l'appareil.");
    }, ACK_TIMEOUT_MS);
    return () => clearTimeout(timer);
  }, [pendingLed]);

  const toggleLed = () => {
    const next = led === 'on' ? 'off' : 'on';
    setLedError(null);
    setPendingLed(next);
    publish(TOPICS.ledCommand, next);
  };

  const canToggleLed = connection === 'connected' && deviceStatus === 'online' && pendingLed === null;

  return { connection, deviceStatus, reading, led, pendingLed, ledError, canToggleLed, toggleLed };
}

import type { SQLiteDatabase } from 'expo-sqlite';

const DATABASE_VERSION = 1;

export async function migrateDbIfNeeded(db: SQLiteDatabase): Promise<void> {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  let version = row?.user_version ?? 0;

  if (version >= DATABASE_VERSION) {
    return;
  }

  if (version === 0) {
    await db.execAsync(`
      PRAGMA journal_mode = 'wal';
      CREATE TABLE IF NOT EXISTS readings (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        temperature REAL NOT NULL,
        humidity REAL NOT NULL,
        received_at INTEGER NOT NULL
      );
    `);
    version = 1;
  }

  await db.execAsync(`PRAGMA user_version = ${DATABASE_VERSION}`);
}

import { useSQLiteContext } from 'expo-sqlite';
import { useEffect, useState } from 'react';

import { readingRepo } from '@/db/readingRepo';
import { parseDeviceStatus, parseReading, type DeviceStatus, type LedState, type Reading } from '@/features/device/reading';
import { MQTT_URL, TOPICS } from '@/lib/config';
import { useMqtt } from '@/lib/useMqtt';

// Declared once, outside the hook: the same array on every render.
const SUBSCRIPTIONS = [TOPICS.sensors, TOPICS.status, TOPICS.ledState];
const ACK_TIMEOUT_MS = 5000;

export function useDevice() {
  const db = useSQLiteContext();
  const [reading, setReading] = useState<Reading | null>(null);
  const [deviceStatus, setDeviceStatus] = useState<DeviceStatus>('unknown');
  const [led, setLed] = useState<LedState>('unknown');
  const [pendingLed, setPendingLed] = useState<'on' | 'off' | null>(null);
  const [ledError, setLedError] = useState<string | null>(null);
  const [savedCount, setSavedCount] = useState<number>(0);

  // At startup, read how many readings the database already holds.
  useEffect(() => {
    let isCurrent = true;
    readingRepo(db)
      .count()
      .then((n) => {
        if (isCurrent) {
          setSavedCount(n);
        }
      })
      .catch((e: unknown) => console.error(e));
    return () => {
      isCurrent = false;
    };
  }, [db]);

  const saveReading = async (next: Reading) => {
    try {
      const repo = readingRepo(db);
      await repo.add(next);
      setSavedCount(await repo.count());
    } catch (e) {
      console.error(e);
    }
  };

  const { status: connection, publish } = useMqtt({
    url: MQTT_URL,
    topics: SUBSCRIPTIONS,
    onMessage: (topic, payload) => {
      if (topic === TOPICS.sensors) {
        const next = parseReading(payload, Date.now());
        if (next) {
          setReading(next);
          // No await: the screen does not wait for the database to show the reading.
          saveReading(next);
        } else {
          console.warn(`[mqtt] ignored payload: ${payload}`);
        }
      } else if (topic === TOPICS.status) {
        setDeviceStatus(parseDeviceStatus(payload));
      } else if (topic === TOPICS.ledState && (payload === 'on' || payload === 'off')) {
        // The device's acknowledgement is the only source of truth for the LED.
        setLed(payload);
        setPendingLed(null);
      }
    },
  });

  // No acknowledgement after 5 seconds: give the button back and explain why.
  useEffect(() => {
    if (pendingLed === null) {
      return;
    }
    const timer = setTimeout(() => {
      setPendingLed(null);
      setLedError("Pas de réponse de l'appareil.");
    }, ACK_TIMEOUT_MS);
    return () => clearTimeout(timer);
  }, [pendingLed]);

  const toggleLed = () => {
    const next = led === 'on' ? 'off' : 'on';
    setLedError(null);
    setPendingLed(next);
    publish(TOPICS.ledCommand, next);
  };

  const canToggleLed = connection === 'connected' && deviceStatus === 'online' && pendingLed === null;

  return { connection, deviceStatus, reading, led, pendingLed, ledError, canToggleLed, toggleLed, savedCount };
}

import type { SQLiteDatabase } from 'expo-sqlite';

export type ReadingRow = {
  id: number;
  temperature: number;
  humidity: number;
  received_at: number;
};

export type ReadingStats = {
  n: number;
  min: number | null;
  max: number | null;
  avg: number | null;
};

type NewReading = { t: number; h: number; receivedAt: number };

// One reading every 5 seconds is 720 rows per hour: keep only the most recent ones.
const MAX_ROWS = 500;

export const readingRepo = (db: SQLiteDatabase) => ({
  add: (reading: NewReading) =>
    db.withTransactionAsync(async () => {
      await db.runAsync(
        'INSERT INTO readings (temperature, humidity, received_at) VALUES (?, ?, ?)',
        reading.t,
        reading.h,
        reading.receivedAt,
      );
      await db.runAsync(
        'DELETE FROM readings WHERE id NOT IN (SELECT id FROM readings ORDER BY id DESC LIMIT ?)',
        MAX_ROWS,
      );
    }),
  count: async () => (await db.getFirstAsync<{ n: number }>('SELECT COUNT(*) AS n FROM readings'))?.n ?? 0,
  latest: (limit: number) =>
    db.getAllAsync<ReadingRow>('SELECT * FROM readings ORDER BY id DESC LIMIT ?', limit),
  stats: async (): Promise<ReadingStats> =>
    (await db.getFirstAsync<ReadingStats>(
      'SELECT COUNT(*) AS n, MIN(temperature) AS min, MAX(temperature) AS max, AVG(temperature) AS avg FROM readings',

});

import { useSQLiteContext } from 'expo-sqlite';
import { useEffect, useState } from 'react';

import { readingRepo, type ReadingRow, type ReadingStats } from '@/db/readingRepo';

const HISTORY_SIZE = 50;

export function useReadings() {
  const db = useSQLiteContext();
  const [readings, setReadings] = useState<ReadingRow[]>([]);
  const [stats, setStats] = useState<ReadingStats>({ n: 0, min: null, max: null, avg: null });
  const [isLoading, setIsLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);
  const [reloadCount, setReloadCount] = useState<number>(0);

  useEffect(() => {
    let isCurrent = true;

    const load = async () => {
      try {
        const repo = readingRepo(db);
        const [rows, summary] = await Promise.all([repo.latest(HISTORY_SIZE), repo.stats()]);
        if (isCurrent) {
          setReadings(rows);
          setStats(summary);
          setError(null);
        }
      } catch (e) {
        console.error(e);
        if (isCurrent) {
          setError('Lecture de la base impossible.');
        }
      } finally {
        if (isCurrent) {
          setIsLoading(false);
        }
      }
    };

    load();

    // Cleanup: a slow answer from an older effect must not overwrite a newer one.
    return () => {
      isCurrent = false;
    };
  }, [db, reloadCount]);

  // Changing reloadCount changes a dependency, so the effect runs again.
  const reload = () => setReloadCount((count) => count + 1);

  const clear = async () => {
    await readingRepo(db).clear();
    reload();
  };

  return { readings, stats, isLoading, error, reload, clear };
}

      </Link>

      <Text style={styles.text}>LED : {ledLabel(device.led)}</Text>

        onPress={device.toggleLed}
        disabled={!device.canToggleLed}
        accessibilityRole="button"

          {device.pendingLed

        </Text>
      </Pressable>

    </ScrollView>
  );
